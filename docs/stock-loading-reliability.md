# 个股反复进入时加载失败 · 2026-10-29

## 复现及原因

模拟两轮依次进入6只个股，每次并发请求首屏配对、综合分析、行情及走势，共48个请求。首屏 `/api/chart-bundle` 的12次调用中有3次 HTTP503，标题明确为 `Worker exceeded resource limits`，其中包括300545、300031和300110；这些股票同轮报价和综合分析均成功。故障是云端重算配对被资源终止，不能一概归因于行情源没数据。

客户端将首次画图只绑定在该接口，又没有跨页面保留成功的配对快照。同一股票进出时会重复发起请求；即使其他请求成功，也可能仍看到整张图不可用。这是首屏改成配对时引入的可用性回归。

Cloudflare过去24小时截至UTC 2026-10-29 00:11的采样，guanlan有260次资源超限、4692次成功和172次断开；这不是整个账户费用，也不能只凭这些数字确定每次失败是CPU还是内存。本次直接复现的错误已足以定位首屏计算链路，D1不参与该路径。

## 修复

- iOS使用随安装包发布的同一份共享TypeScript策略，经esbuild打包，在JavaScriptCore专用后台队列计算。请求 `/api/chart-frame` 只取得已核验复权基准的行情及报价，不在Worker重放整套形态／策略。K线和标注仍核验同组OHLCV、MA、标的后同帧绘制。
- 本机保留五线指南、股性、原有交易计划、风险提示和历史规则跟踪；资金、板块等通过 `/api/review-context` 独立取得事实，再用同一复核函数合成。可选来源失败不抹掉已经可用的图表及本机分析，缺失证据继续显示未核验。
- 公共GET请求合并正在执行的相同请求，短时复用成功结果；不缓存错误，不缓存带认证令牌的私有接口，不恢复盘中全市场定时扫描。
- 最近8只股票保存原始成功行情到设备；再次进入先在本机生成完整配对快照，再后台刷新。过期快照明确标注且报价置为stale，避免冒充实时入场建议。缓存仅保留7天；未取得过数据且完全断网时不能制造行情。
- 云端历史单独保留最后成功版本，短时复用，源失败时最多回退到24小时内同标的版本并标明过期。窗口、均线、代码和价量改变都会触发对应重算，保持原来的行情刷新频率。
- 页面退出或MA切换后停止应用过时结果；本机计算超时有上限，暂时失败有限重试。设备缓存写失败不丢弃已经成功取得的新行情。

## 验证及更新约束

`tests/local-study.test.ts`在没有fetch和DOM的隔离JS环境中，对经典／斐波那契、日／周／月六组结果与共享源逐项比对形态、买卖点、指标和走势状态。Dart验证重复进入合并请求、错误后恢复、离线重开保留同组行情、更改MA重新计算。iOS集成测试直接调用实际JavaScriptCore，禁止计算网络请求，并检查上下行两种状态及最后一根OHLCV。

部署后按相同6只股票、两轮、每轮4个并发端点复测48个请求，全部成功；新行情首屏12次均成功，墙钟耗时中位257ms、最大1425ms。该统计只测数据传输，手机本机计算另由原生测试验证，不把墙钟耗时当成Cloudflare计费CPU时间，也不把12次成功宣传为所有股票／网络永远零失败。

每次共享规则更新必须运行 `npm run build:mobile-engine`，重新发布iOS包。CI用 `node tools/build-mobile-engine.mjs --check`拒绝源规则与打包引擎不一致。此改动需要安装新App，仅刷新网站不能替换旧App的加载链路。公开源或网络仍可能中断；保留快照提高可用性，不构成行情来源SLA。

## 本轮修复

- 策略与图表复用同次调用的形态证据和指标，避免重复扫描；使用弱引用，不在 API JSON 中重复传输大数组。
- 公开原始日线结果使用边缘缓存 120 秒，盘中价量仍走独立快照；综合分析、自选洞察和走势分析 15 秒；相同 OHLCV／MA／标的／当日收盘阶段的标注内容寻址缓存 300 秒。错误不缓存，浏览器仍使用 no-store。此缓存不承诺全网命中，也不能保证免除冷计算开销。
- 经典／斐波那契共 6 组真实数据回放由约 80–110ms 降为约 50–67ms，本地耗时减少约 35–45%；加上默认参数共 9 组输出逐项一致。这是本机对比，不是 Cloudflare CPU 计费时间。
- 手机原始日 K 独立于综合分析加载；分析失败不再挡住图表。
- 手机保持原有行情及标注更新频率，仅跳过完全相同输入、合并正在执行期间到来的更新；不通过降低实时性节约计算。首次失败最多两次延迟重试，避免重建界面形成请求循环。历史有效标注保留，新 MA／新标的不会冒用旧参数结果。
- 手机新增独立「标注设置」入口，并在均线参数里提供入口；形态、买卖点、指标标注、MA 交叉分别控制，保存在设备。指标标注包含 MACD/KDJ 交叉、背离和 VOL 量能文字。
- Cloudflare HTML 错误被转为可理解的计算资源提示，不再显示 JSON 解析乱码。

## 应优先加强什么

先确认 Workers 订阅与 CPU 限制。如果仍是 Free，完整 500 根策略的冷计算明显难以稳定压进 10ms，Workers Paid 比增加 D1 更直接。Paid 官方最低 $5/月，包含 1,000 万请求和 3,000 万 CPU 毫秒/月；超额另计，不能保证最终账单只有 $5。建议先给分析 Worker 配置约 1,000ms 的单次 CPU 保护上限，再根据实际 P95/P99 调整；这不是自动开通指令。

网络等待不计入 CPU，增加 CPU 不会修好东财连接超时。D1 将来适合保存行情版本、历史信号与可回放研究快照；接入时必须配好索引、有效期和复权版本，不是现在立即扩容的前提。
